# Internationalization (i18n) Standards

Airmedy uses `vue-i18n` for frontend localization. All user-facing strings must be localized.

## 1. Localization Files

- **Location:** `frontend/src/locales/`
- **Format:** JSON files, one per language.
- **Supported languages (12):** `de`, `en`, `es`, `fr`, `it`, `ja`, `ko`, `pt`, `ru`, `th`, `vi`, `zh`
- **Structure:** Group keys by component or feature (e.g., `settings`, `player`, `library`).

## 2. Implementation Rules

- **No hardcoding:** NEVER hardcode strings in templates or scripts. Use `$t()` in templates or `t()` from `useI18n()` in scripts.
- **No inline fallbacks:** Do NOT write `t('key', 'Fallback')`. Strings must exist in locale files.
- **Full synchronization:** ALL 12 language files MUST be kept in sync. Adding a key to any one file means adding it to all 12.
- **Workflow-first:** Add keys to ALL locale files before using them in components.

## 3. Workflow for New Strings

1. Identify the needed string.
2. Add the key to **all 12 locale files simultaneously** — English value in `en.json`, translated values (or English placeholder) in the other 11.
3. Use the key in the Vue component:
    ```vue
    <!-- Template -->
    <span>{{ t('category.feature.label') }}</span>

    <!-- Script -->
    const { t } = useI18n()
    const label = t('category.feature.label')
    ```
4. Verify the string renders correctly in the UI.

## 4. Package Manager

Use `pnpm` for all frontend commands (not `npm` or `yarn`).
