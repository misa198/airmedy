# Internationalization (i18n) Standards

Airmedy uses `vue-i18n` for frontend localization. All user-facing strings must be localized.

## 1. Localization Files
- Location: `frontend/src/locales/`
- Format: JSON files (e.g., `en.json`, `zh.json`, `vi.json`).
- Structure: Group keys by component or feature (e.g., `settings`, `player`, `library`).

## 2. Implementation Rules
- **Prose:** NEVER hardcode strings in templates or scripts. Use `$t()` in templates or `t()` from `useI18n()` in scripts.
- **Fallbacks:** Do NOT provide inline fallbacks (e.g., `t('key', 'Fallback')`) in the code. Strings must exist in the locale files.
- **Full Synchronization:** ALL language files (`en.json`, `zh.json`, etc.) MUST be kept in sync. When adding a key to `en.json`, you MUST also add it to all other language files, using translations where possible.
- **Workflow:** Add keys to ALL locale files first, then use them in components.

## 3. Workflow for New Strings
1.  Identify needed string.
2.  Add key and English value to `frontend/src/locales/en.json`.
3.  Use the key in the Vue component:
    ```vue
    <!-- Template -->
    <span>{{ t('category.feature.label') }}</span>

    <!-- Script -->
    const { t } = useI18n()
    const label = t('category.feature.label')
    ```
4.  Verify the string renders correctly.
